## 检查

主要有几个缺陷：
- 记不住每层的名字；
- L2和L3具体数值和细节有混淆，没有正确区分 对话，message，tool_result 谁作为单位


### L2 纠错部分

- L2 的保留单位是 **最近 3 条 tool_result 块**（KEEP_RECENT_TOOL_RESULTS = 3），_不是“最后3轮对话”_。一轮对话可能包含多个 tool_result 块（比如连续执行多条命令），L2 是按块计数，而非按消息轮次。
- L2 的替换阈值是 内容长度 > 120 字符，_不是 200KB。200KB 是 L3 的阈值_。
- L2 本身不依赖任何大小阈值（120 字符只是一个简单的“太短就不替换”的保护）

正确表述：L2 将除了最后 3 条 tool_result 块之外的所有较长的旧 tool_result 替换为占位符（内容长度 > 120 字符的才替换）。

### L3 纠错部分

- L3 的目标对象（最后一条 user message 中的所有 tool_result）、从大到小替换、直至总大小 ≤ 200KB
- 持久化方式是：每个 tool_result 单独存为一个 txt 文件，内容为原始输出全文

正确表述：L3 将超大的 tool_result 持久化为 `tool_use_id.txt` ，并在上下文中保留 <persisted-output> 标记和预览。
