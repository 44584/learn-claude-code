s09 review

文件系统 + 索引 + 按需调取 + 每轮对话后形成和压缩 + 跨session

文件系统: 每个记忆使用单个 YAML md 文件, 具体来说与 SKILL.md 格式类似, "---" + name, description, type元信息 + "---" + 具体内容

索引: 与md文件同级还有一个索引文件MEMORY.md, 每一行指向一个记忆文件

按需调取:

- 每个记忆的name和description形成catalog信息, 和索引文件常驻SYSTEM PROMPT (_不太清楚是不是仅仅索引文件常驻_ **仅索引文件常驻**);
- 按需调取是通过LLM实现, 这是一个aside的
- 一轮对话(turn)中的记忆注入是临时的, 不会进入messages

每轮对话形成记忆和压缩:

- 首先在压缩前保存messages快照
- 然后将messages的文本信息 和 记忆信息(_全部 or catalog_ **catalog**) 一并发送给LLM
- 得到 压缩后 + 添加新记忆 的新一轮记忆, 索引文件和记忆文件一并更新了

# 检查知识遗漏

索引放在SYSTEM PROMPT中, 让主模型知道有哪些记忆存在、并约束它的行为（尊重偏好、主动写记忆）.

## 按需调取记忆

在请求时, 使用side-query,将

1. 最近对话\(最多三条user对话\)
2. 记忆的catalog\(name+description\)
   发给LLM, 得到索引, 选出相关的记忆文件名

注入的记忆内容会进入发给 API 的请求（s09_memory/code.py:830）。进入请求副本，不进入持久历史，用完即弃。

## 关于记忆的管理(提取和整理)

### extract

在每轮\(turn\)对话结束时, 即`stop_reason != "tool_use"`时, 使用

1. 最近10条message
2. 现有catalog

发送给side LLM, 得到返回的{name, type, description, body} 数组, 写新文件并更新索引.

### consolidate

每轮\(turn\)对话结束, 检查文件数是否大于10, 若是, 则通过LLM完成记忆文件的去重合并.

# 记忆类型

四类记忆类型：user（你是谁）/ feedback（怎么做事）/ project（正在发生什么）/ reference（东西在哪找）

# 时序总结

```
  用户输入
   ├─ side-query：最近对话 + catalog → LLM 选索引（不进 SYSTEM，也不进 history）
   ├─ build_system()：读 MEMORY.md → SYSTEM（每轮重建，内容常驻）
   ├─ pre_compress 快照 ← 压缩前的 messages
   ├─ 压缩管线 → 主 LLM 调用（可多步循环）
   └─ 回合结束（stop_reason != "tool_use"）
      ├─ extract_memories(pre_compress) → 新记忆写文件 + 重建索引
      └─ consolidate_memories()（≥10 文件时）
```
